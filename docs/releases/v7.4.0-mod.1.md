# v7.4.0-mod.1 — labeled grid, blank-capture rescue, humanize, scancode keys

Local mod on top of upstream v7.4.0 (2026-10-08). All changes are additive and
degrade silently: any new rendering step that fails returns the original image,
and every new parameter is optional with the old behavior as default.

## Labeled coordinate grid on `screenshot` and `snapshot`

- New `grid_lines=[cols,rows]` parameter on `screenshot` (snapshot already had
  it). Both now render the same matplotlib-style overlay in pure TypeScript
  (`src/session/image-grid.ts`, no native rebuild needed): gray grid lines,
  numeric tick labels in **absolute screen pixels**, `X/Y Coordinate (px)`
  captions, and a light/dark adaptive frame. Labels live in frame padding so
  they never cover content. An agent reads a number and clicks it directly.
- `snapshot` no longer uses the native plain-line grid; boxes stay native,
  the labeled grid is drawn on top in TS.
- Implementation: `jpeg-js` + `pngjs` (pure JS, added to dependencies) and an
  embedded 5x7 bitmap font — no OS font dependency.

## Blank-capture rescue (`screenshot` window targets)

Window captures of GPU-composited windows (browsers, games, Electron) via GDI
BitBlt come back valid-but-blank. When a window-targeted frame decodes to a
(near-)uniform image, `screenshot` now re-captures the screen at full
resolution and crops to the window bounds (`cropImage`), appending a fallback
note to the mapping text. A genuinely blank window (empty Notepad) also
matches, which is harmless — the crop shows the same content.

## Humanize

Optional `humanize: true` on `left_click`, `right_click`, `middle_click`,
`double_click`, `triple_click`, `mouse_move`, `left_click_drag`, `mouse_drag`,
`left_mouse_down/up`, `scroll`, `type`, `key`, `multi_select`, `multi_edit`:
quadratic-Bezier pointer paths with random bow, ease-out pacing and exact
endpoints; jittered per-character typing with occasional pauses; jittered key
repeats. Slightly slower, much harder to fingerprint as synthetic.

## Always-move clicks

Every press path now moves to the point first (hover fires): already true for
clicks/drags/scroll, added for `left_mouse_down`. `left_mouse_up` stays put
so down-elsewhere + up-here drags keep working.

## Lower-level keys (native, `native/src/keyboard.rs`)

`send_key` now resolves the hardware scancode (`MapVirtualKeyW`,
`MAPVK_VK_TO_VSC_EX`) and sends `KEYEVENTF_SCANCODE` with `wVk: 0`
(+ `EXTENDEDKEY` for arrows/home-end/RWin/…). Falls back to the old VK-only
form when no scancode exists. Verified live: `key a` + `type` + humanized
clicks land in Notepad. Unicode text batching is unchanged.

Honest ceiling (unchanged): `SendInput` sets the `INJECTED` flag and UIPI
still applies — kernel anticheat and elevated windows are out of reach for
any user-mode software. No scancode key exists for that either.
